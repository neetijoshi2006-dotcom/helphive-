1. WHAT IS NORMALIZATION?
------------------------------------------------------------------------
Normalization is the process of organizing data in a database to avoid:
- Data Redundancy (duplicate data)
- Insertion Anomalies (inability to insert data because of missing attributes)
- Update Anomalies (inconsistent updates due to duplicate records)
- Deletion Anomalies (unintentional loss of data during deletions)

------------------------------------------------------------------------
2. DATABASE KEYS EXPLAINED
------------------------------------------------------------------------
* Super Key: A set of one or more attributes that uniquely identifies a row.
* Candidate Key: A minimal super key (no redundant attributes).
* Primary Key: The selected candidate key used to identify rows uniquely.
* Alternate Key: Candidate keys not chosen as the primary key.
* Foreign Key: An attribute in a table that references the primary key of another table.

------------------------------------------------------------------------
3. NORMAL FORMS (1NF to BCNF)
------------------------------------------------------------------------

--- First Normal Form (1NF) ---
Rule: Atomic Values only (no multi-valued or composite attributes).
Example: If a "Phone" column has multiple numbers separated by commas, split them into separate rows or a relational table.

--- Second Normal Form (2NF) ---
Rule: Must be in 1NF AND have no partial dependencies.
* Partial Dependency: A non-prime attribute depends on only a part of a composite primary key.
Solution: Separate the partially dependent attributes into a new table.

--- Third Normal Form (3NF) ---
Rule: Must be in 2NF AND have no transitive dependencies.
* Transitive Dependency: A non-prime attribute depends on another non-prime attribute (X -> Y and Y -> Z).
Solution: Split the relation such that for every functional dependency X -> Y, either X is a super key or Y is a prime attribute.

--- Boyce-Codd Normal Form (BCNF) ---
Rule: Strict version of 3NF. For every functional dependency X -> Y, X MUST be a Super Key.
Key differences: BCNF does not allow Y to be a prime attribute if X is not a super key.
